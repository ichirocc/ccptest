# インターバル・バブルカメラ

個人所有のAndroid 16以降の端末向けに、1〜60秒間隔で端末の全カメラで撮影し、どれかで動体があったときだけ全カメラの写真をそろえて保存するアプリです。撮影開始後はアプリがバブルになり、他のアプリを使っている間や画面ロック中もインターバル撮影を継続します。画面表示は日本語のみです。

## 主な機能

- 1〜60秒の撮影間隔（1秒刻み）
- フラッシュは使いません（全カメラでフラッシュをオフに固定）
- 端末が公開している全カメラ（背面の広角・超広角・望遠、前面など）で撮影。毎回1台ずつ切り替えて撮影
- 端末のカメラの力をできるだけ使う（どれもカメラが対応しているときだけ。つなげない・撮れないカメラはふつうの撮り方に戻す）
  - 全画素で撮影（Pixel 10 Pro XL などの高性能機。5000万画素のセンサーは、ふだん4画素を1つにまとめた1250万画素で撮られるため。本体がやや熱いとき・夜景モードではふつうの画素数）
  - 遅れの少ない撮影（ZSL: カメラが流し続けている映像から撮った瞬間の1枚を取り出す）
  - 光学式手ぶれ補正・高品質のノイズ除去・高品質の輪郭の処理を、撮影ごとに指定
  - Ultra HDR（明暗の幅が広い写真。ふつうの JPEG として読めて、対応した画面では明るい所がより明るく見える）で保存。写真の向きは Exif の中でその場で書き換えるので、Ultra HDR の情報（ゲインマップ）も壊れない
- 常に動体検知（カメラごとに前回の画像と比べ、どれかで動体があれば全カメラの画像を保存。判定の閾値はユーザーが設定）
- 動いている人を端末内の検出で確認して追跡（すべて MediaPipe Tasks、端末内のみで処理）
  - 全身・大部分が写った人と車など: 物体検出（EfficientDet-Lite0）
  - 体の一部（上半身だけ・脚だけなど。足首・つま先を含む）: 姿勢推定（Pose Landmarker lite、見えている関節だけで枠を作る）
  - 手だけ: 手の検出（Hand Landmarker）
  - 検出した対象を撮影ごとにつないで同じIDで追跡し、変化と重なる、または前回から位置が動いた対象があるときだけ保存。ピントはその対象（人を車より優先）の中心に合わせる
  - スマホの向き（上下逆さ・左右の横向き・平らに置いたとき）に関係なく人を検出。まずスマホの向きから見て正立の向きで探し、人が見つからなければ画像を90°・180°・270°回した向きでも探す（寝ている人なども見つかる）
  - 論文の手法を取り入れた検出（新しいモデルは追加せず、同梱のモデルのまま）
    - ByteTrack（Zhang et al., ECCV 2022）: 確からしさの低い検出（0.2〜0.4）は、追跡中の人の続きとしてだけ使う。半分隠れた・ぶれた人を見失いにくく、低い検出だけで誤って人を増やさない
    - SAHI（Akyon et al., ICIP 2022）: 画像が変わったのに、その変化を説明する人が見つからなければ、変化した辺りを撮影画像から高い解像度で切り出して探し直す（遠くの小さな人を見つける）
    - Weighted Boxes Fusion（Solovyev et al., Image and Vision Computing 2021）: 向きや切り出しを変えて重ねて見つけた同じ人は、捨てずに確からしさで重みをつけた平均の枠にまとめる
  - カメラごとに、画角（焦点距離とセンサーの幅から求める横の画角）に合わせて検出を調整（アプリ画面の「人の検出」に表示）
    - 超広角（85°以上）: 人が小さく写るので、検出に渡す画像を1.5倍にし、変化した辺りを切り出すときはより大きく拡大する。画面の上ではあまり動かないので、0.02動けば動いたとみなす
    - 広角・前面: これまでどおり（0.03動けば動いたとみなす）
    - 望遠（40°以下）: 人が大きく写るので、検出に渡す画像を0.75倍にして速くする。少し動いただけで画面の上では大きく動くので、0.045動いたら動いたとみなす
  - 検出を使えない端末では画像の変化だけで判定
- 動体の閾値を2つのスライダーで設定。前回の画像と比べて「変化の大きさ」を超える部分が画面の「変化の広さ」以上あり、その変化が人や車に重なると保存。閾値に届かなくても、人や車の位置が前回から動いていれば保存（変化の大きさ＝明るさの差 5〜100、変化の広さ＝画面に占める割合 0.1〜20.0%。既定は 28・1.0%）
- カメラを切り替えるたびに、そのカメラの自動露出・自動ホワイトバランス・自動ピントが落ち着くまで待ってから撮る（カメラが毎コマ知らせる状態を見る。最低0.1秒、最長は機種ごとの待ち時間の2倍。夜景モードは状態が届かないので機種ごとの待ち時間だけ待つ）。暗い所では長めに、明るい所ではすぐに撮れる
- 撮影のたびに、各カメラで最後に動体があった位置（まだ無ければ画面中央）にピントを合わせてから撮影（露出は画面全体でカメラに任せる）。動体を検知したカメラは、その位置にピントを合わせ直して撮り直してから保存（ピント合わせに非対応のカメラはそのまま保存）
- ステータスバー領域と左右半分の画面外まで移動できるフローティングバブル
- 画面ロック中もCPUを起動状態に保って撮影を継続
- 添付画像を使用した「19＋」をアプリアイコンに設定
- フローティングバブルを7色から選択（ブラックを含み、選択を端末内に保存）
- バブルをタップしてアプリへ復帰
- 常駐通知から撮影停止
- 撮影状況はアプリ画面にだけ表示（状態・保存枚数と見送り回数・直近の出来事・最終保存ファイル・使っているカメラと撮り方・検出の実行先・直近で撮れなかったカメラ）。ステータスバーや常駐通知には情報を出さない（常駐通知はAndroidの決まりで必要なため、文字は出さず停止ボタンだけ）
- 写真を `Pictures/IntervalBubbleCamera` に保存
- 同梱画像を切らずに没入型の全画面で表示（画面タップまたは戻る操作で終了）
- 外部送信なし（インターネット権限も未使用）

## 画面の言葉

アプリの画面は、小学5年生でも分かる言葉にしています（5年生までに習う漢字だけを使い、むずかしい言葉は使わない）。手順は「① とり方を えらぶ → ② バブルの色を えらぶ → ③ はじめに すること → スタート」の順に並べています。カメラ・人の検出・本体の温度・撮れなかったカメラなどのくわしい情報は、「くわしい情報（おとな向け）」を押したときだけ出します。

## 動作条件

- Android 16（API 36）以降
- 個人所有端末での利用を前提
- カメラを搭載した実機
- Android Studio Meerkat 2024.3.1以降を推奨
- JDK 17
- Android SDK 36

## ビルドとインストール

1. Android Studioでこのリポジトリを開きます。
2. Android SDK 36が未導入なら、SDK Managerから追加します。
3. USBデバッグを有効にしたAndroid実機を接続します。
4. `app` 構成を選び、Runを押します。

プルリクエストを作る・更新するたびと main に入るたびに、GitHub Actions の CI（`.github/workflows/ci.yml`）がユニットテストとデバッグ APK のビルドを行います。

コマンドラインの場合:

```bash
./gradlew testDebugUnitTest assembleDebug
adb install -r app/build/outputs/apk/debug/app-debug.apk
```

## 使い方

1. 「① とり方を えらぶ」で撮り方を選びます（迷ったら「おすすめ（まよったら これ）」）。撮影間隔と動体検知の閾値（変化の大きさ・変化の広さ）がまとめて決まります。暗さ・手ぶれ・本体の温度・カメラの画角は、どの撮り方でも自動で合わせます。
   - おすすめ: 10秒ごと・変化の大きさ28・変化の広さ1.0%
   - 屋外・遠くの人: 5秒ごと・22・0.3%（遠くの小さな人の動きも拾う）
   - 室内・近くの人: 10秒ごと・32・2.0%（照明のちらつきなど小さな変化では保存しない）
   - 長時間・電池優先: 30秒ごと・28・1.0%
   - 自分で決めたいときは「くわしく 決める」を開いてスライダーを動かします（撮り方は「自分で 決める」になります）。保存してある値がどれかの撮り方と同じなら、その撮り方が選ばれた状態で開きます。
1. バブルの色を選びます。
2. 「スタート（とりはじめる）」を押します。
3. 初回だけ、カメラ・通知・他のアプリ上への表示を許可します。
4. カメラ準備後にアプリが背面へ移動し、バブルが表示されます。
5. 必要なら、撮影中であることを確認してから画面をロックします。
6. バブルをドラッグして移動、タップしてアプリへ戻れます。
7. 停止はアプリ画面または常駐通知の「停止」から行います。
8. 動体検知は常に有効です。最初の1回は比較用で保存されず、以降はカメラごとに前回の画像と比べ、どれかで動体があったときだけ全カメラの画像を `IBC_MOTION_<日時>_<カメラ>.jpg`（例: `_back0`・`_back2`・`_front1`。数字は端末のカメラ番号）として保存します。
9. 「絵を 大きく 見る」を押すと同梱画像が開きます。画像をタップするか戻る操作で閉じます。

## Androidの制約と注意点

- Androidのプライバシー仕様により、撮影中はカメラ使用インジケーターと常駐通知が表示されます。非表示にはできません。
- 7色設定で変わるのはバブルの色だけです（ホーム画面のアプリアイコンは変わりません）。ブラックを選んでも、Android右上の緑色カメラ使用表示の色は変更されません。
- Android 16以降のバックグラウンドカメラ制約に対応するため、撮影サービスは必ず画面ロック前かつアプリ画面が前面にある状態で開始します。その後はカメラ用フォアグラウンドサービスとして継続します。
- 画面ロック中は部分Wake Lockを撮影ごとに更新します。停止時や異常終了時には必ず解放します。
- 前後同時撮影は使いません（Androidの同時撮影は解像度が1920×1440に制限され、Pixel 10 Pro XLでは露出も合いにくかったため）。毎回カメラを切り替えて撮り、切り替え1回に約1秒かかるため、各カメラの撮影時刻は少しずつずれます。またカメラが多いと短い間隔では設定より間隔が延びます。
- ピントは動いた画素の重心に合わせ、以降の撮影もその位置に合わせます。ピント合わせは1台あたり最大2秒、動体を検知したカメラは撮り直しの分さらに長くかかるため、短い間隔では設定より間隔が延びます。
- 超広角や望遠をアプリに公開していない機種では、それらのカメラは使えません。背面のメインカメラと、その中の物理カメラ（広角など）が両方撮影されるため、似た画像が2枚保存されることがあります。
- 動体検知は撮影画像を80×60画素の輝度画像に縮小し、明るさ全体の変化（自動露出）を差し引いてから、変化した画素の割合で判定します。
- スマホ自体が動いた回（手持ちのぶれ・向きの変化）は動体として扱いません。スマホの向きのセンサー（ジャイロ）で前回の撮影から2°以上回ったら「スマホが動いた」とみなします。その回は、画面全体のずれ（最大で画角のおよそ1割）を求めて前回の画像を重ね直してから比べ（手ぶれ補正と同じ考え方）、それでも変わったところや、ずれを打ち消しても位置が動いた人があれば保存します。追跡中の人の位置も同じだけずらして追跡を続けます。スマホが動いていて、撮影している人も歩いているときは、写っているものに関係なく保存します。歩いているかは、加速度を重力の向きにそろえた上下の成分で見て（スマホの持ち方によらない。RoNIN: Herath et al., ICRA 2020）、その揺れが1歩ごとにくり返しているか（直近3秒の揺れを1歩ぶん=0.3〜1.0秒ずらした自己相関が0.6以上、揺れの大きさが1 m/s²以上）で判定します。歩きながら撮るときは、ジャイロで測った回転の速さが小さくなる瞬間（1歩ごとの揺れの合間）を最大0.7秒待ってから撮り、ぶれを減らします（ジャイロでカメラの回転を測る: Shi et al., WACV 2022）。それ以外で重ね直せないほど大きく動いた・その場で回したときは、画像の変化や位置の移動では判定せず、追跡もやり直します。ただし人（全身・体の一部・手）が写っていれば保存し、ピントはその人に合わせます（車などだけでは保存しません。人が写っていなければアプリ画面に「スマホが 動いたので、写真は のこしませんでした」と表示）。ジャイロが無い端末では重力の向き（加速度センサー）で傾きの変化を見て、平らに置いたまま傾きが変わらなければ止まっているとみなします。どちらでも分からないときだけ、画面の半分以上が変わったかで判定します（スマホが止まっていれば、近くの人が画面の大半を占めても保存します）。
- スマホの上を人がまたいだときなど、スマホが止まっていて画面の30%以上が変わったら、すぐ近くを人が覆ったとみなし、人を検出できなくても保存します（真下や真横から見た人は検出できないことが多いため）。手持ちでも使えますが、取りこぼしを減らすには固定して使うのがおすすめです。
- 人の検出は全カメラで撮影のたびに動かします。画像の変化が閾値未満でも、前回から位置が動いた人を拾えるので、ゆっくり歩く人や遠くの人も追えます。風で揺れる木や光の変化だけでは保存しません。毎回検出する分、電池と発熱は増えます。正立以外の向きでも人を探すのは、画像が変わった・追跡中の人がいる・スマホが動いた回だけです。
- 速く撮れるように、撮影した画像は1回だけ縮小して読み込み、動体検知と人の検出で使い回します。動体があった回の保存は裏で行い、書き込みを待たずに次の撮影へ進みます。人の全身が見つかった向きでは体の一部や手は探さず、同じカメラでピントの位置が変わらなければ合わせ直しません（30秒ごとには合わせ直します）。
- 発熱対策として、本体の温度（Androidの温度の状態と、10秒先の温度の見込み）に応じて負荷を自動で下げます。熱くなりきる前から下げ始め、今の段階はアプリ画面の「本体の温度」に表示します。
  - 普通: 設定どおり
  - やや熱い: 人の検出は正立の向きだけ・撮影間隔5秒以上・1周ごとに2秒以上休む
  - 熱い: 人の検出を止めて画像の変化だけで判定・撮影間隔15秒以上・1周ごとに5秒以上休む
  - とても熱い: 人の検出を止める・撮影間隔60秒・1周ごとに30秒以上休む
- 足だけが写っている場合は、脚の一部も写っていないと検出できないことがあります（足先だけを検出できる端末内モデルが無いため）。
- 検出モデル5つ（両機種用、合計約35MB）と実行部品の分、アプリが大きくなっています。
- 照明が暗いときは夜景モード、明るいときは普通のモードに自動で切り替えます。明るさはスマホの照度センサーで測り、10ルクス未満で夜景モード、30ルクスを超えたら普通のモードに戻します（境目で行ったり来たりしないよう間を空けています）。夜景モードはメーカーのカメラ拡張機能（CameraX Extensions）を使うため、対応するカメラ（Pixel 10 Pro XLでは背面メイン・前面の想定）だけが夜景モードになり、超広角・望遠などの物理カメラは普通のモードのまま撮ります。夜景モードの撮影は1枚に数秒かかります。モードを切り替えた直後の1回は比較用で保存しません。照度センサーが無い端末では普通のモードのままです。
- 夜間・暗い場面（平均の明るさが60未満）では、前回との差から雑音（ざらつき）を明るさごとに見積もり（雑音の分散＝a×明るさ＋b。ELD: Wei et al., CVPR 2020 の物理モデル）、画素ごとにその明るさの雑音の3倍（2枚の差なので×√2）以上の変化だけを数えます。雑音だけで「動いた」と誤って保存しないためです。また人の検出に渡す画像だけを、Zero-DCE（Guo et al., CVPR 2020）の明るくする曲線 x＋α·x(1−x) を8回かけて、平均の明るさが論文の露出の目標0.6になるよう明るくします（保存する写真は変えません）。
- 手持ちのぶれ対策として、毎回スマホがほぼ止まった瞬間（ジャイロの回転の速さが0.35 rad/s以下）を手持ちなら最大0.4秒、歩きながらなら最大0.7秒待ってから撮ります。止まっていれば待ちません。さらに、保存しそうな写真の手ぶれをジャイロで見積もり（露出中の回転の速さ×露出時間×焦点距離。Shi et al., WACV 2022 と同じくジャイロでカメラの回転を測る）、像の流れが画像の幅の0.2%を超えていれば、止まった瞬間を待って1回撮り直し、ぶれの小さいほうを保存します。
- 速く・熱を出さないように、画像が変わっておらず追跡中の人もいない回は、重い人の検出を省きます（Reducto: Li et al., SIGCOMM 2020。続けて省くのは普通のとき2回、やや熱いとき4回まで）。やや熱いときは検出に渡す画像を0.7倍に縮めます（ApproxDet: Xu et al., SenSys 2020）。温度の段階は、端末が熱で性能を絞る前に温度の見込みで先に下げ、見込みが十分下がるまで（入った値より0.05下がるまで）戻しません（zTT: Kim et al., MobiSys 2021。境目で負荷を上げ下げし続けないため）。
- 撮れなかったカメラがあると、少し待って1回だけ撮り直します。撮れなかったカメラはアプリ画面に表示し、理由は端末の動作記録（logcat）に残します。
- 対象機種（Pixel 10 Pro XL・OPPO A5 5G）向けの調整:
  - 機種ごとに性能設定を切り替えます（Pixel 10系または高性能機の条件を満たす端末＝高性能設定、それ以外＝標準設定）。
    - Pixel 10 Pro XL（Tensor G5）: 検出はNPU→GPU→CPUの順に試し、高精度モデル（EfficientDet-Lite2・Pose full）、検出用画像1024px、JPEG画質95、カメラ切り替え後の待ち0.5秒。
    - OPPO A5 5G（Dimensity 6300）: 検出はGPU→CPU、軽量モデル（EfficientDet-Lite0・Pose lite）、検出用画像640px、JPEG画質90、待ち0.8秒。
  - 本体が熱くなったとき（温度状態が「重度」以上）は検出を止め、画像の変化だけで判定します。
  - 白黒や低画素（300万画素未満）の補助カメラ、メインと同じ焦点距離の物理カメラ（同じ画になる）は使いません。Pixel 10 Pro XLでは背面の広角・超広角・望遠と前面、OPPO A5 5Gでは背面のメインと前面を想定しています（実際に使うカメラは端末が公開しているものによります）。
- APKには64ビットARM（`arm64-v8a`）向けの実行部品だけを入れています。対象の実機（OPPO A5 5G・Pixel 10 Pro XL）はどちらも64ビット専用なのでこれで動きますが、x86のエミュレーターでは動きません。
- 1秒間隔は端末の発熱、電池消費、保存容量への負荷が大きくなります。
- 指定値は撮影開始時刻の目標間隔です。カメラの処理が指定間隔より長い場合は、写真を重複して処理せず、前の保存完了後すぐ次を撮影します。
- 極端な省電力モードやメーカー独自のバックグラウンド制限により、ロック中の間隔が遅れたりサービスが停止したりすることがあります。
- カメラを利用する別アプリとは同時に撮影できません。

## 実装概要

- Kotlin / Android Views
- CameraX `ImageCapture`
- `LifecycleService` + `foregroundServiceType="camera"`
- `PARTIAL_WAKE_LOCK`（10分の安全タイムアウトを各撮影前に更新）
- `TYPE_APPLICATION_OVERLAY` のフローティングバブル
- MediaStore / scoped storage
- Min/Target SDK 36（対応OSの上限なし）、CameraX 1.6.1

## プライバシー

写真は端末の共有Pictures領域だけに保存します。アプリはインターネット権限を宣言せず、写真・利用情報を外部へ送信しません。撮影は端末所有者がアプリ画面から明示的に開始した場合に限られ、常駐通知とバブルから状態を確認・停止できます。
