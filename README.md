# インターバル・バブルカメラ

個人所有のAndroid 16以降の端末向けに、1〜60秒間隔で端末の全カメラで撮影し、どれかで動体があったときだけ全カメラの写真をそろえて保存するアプリです。撮影開始後はアプリがバブルになり、他のアプリを使っている間や画面ロック中もインターバル撮影を継続します。画面表示は日本語のみです。

## 主な機能

- 1〜60秒の撮影間隔（1秒刻み）
- 端末が公開している全カメラ（背面の広角・超広角・望遠、前面など）で撮影。前後の1組は対応端末なら同時に撮り、残りは毎回順に切り替えて撮影
- 常に動体検知（カメラごとに前回の画像と比べ、どれかで動体があれば全カメラの画像を保存。判定の閾値はユーザーが設定）
- 動いている人を端末内の検出で確認して追跡（すべて MediaPipe Tasks、端末内のみで処理）
  - 全身・大部分が写った人と車など: 物体検出（EfficientDet-Lite0）
  - 体の一部（上半身だけ・脚だけなど。足首・つま先を含む）: 姿勢推定（Pose Landmarker lite、見えている関節だけで枠を作る）
  - 手だけ: 手の検出（Hand Landmarker）
  - 検出した対象を撮影ごとにつないで同じIDで追跡し、変化と重なる、または前回から位置が動いた対象があるときだけ保存。ピントはその対象（人を車より優先）の中心に合わせる
  - 検出を使えない端末では画像の変化だけで判定
- 動体の閾値を2つのスライダーで設定（変化の大きさ＝明るさの差 5〜100、変化の広さ＝画面に占める割合 0.1〜20.0%。既定は 28・1.0%）
- 撮影のたびに、各カメラで最後に動体があった位置（まだ無ければ画面中央）にピントと露出を合わせてから撮影。動体を検知したカメラは、その位置にピントを合わせ直して撮り直してから保存（ピント合わせに非対応のカメラはそのまま保存）
- ステータスバー領域と左右半分の画面外まで移動できるフローティングバブル
- 画面ロック中もCPUを起動状態に保って撮影を継続
- 添付画像を使用した「19＋」をアプリアイコンに設定
- フローティングバブルを7色から選択（ブラックを含み、選択を端末内に保存）
- バブルをタップしてアプリへ復帰
- 常駐通知から撮影停止
- アプリ画面には撮影状態を表示しない（エラー時だけ短いメッセージで通知。保存枚数は常駐通知に表示）
- 写真を `Pictures/IntervalBubbleCamera` に保存
- 同梱画像を切らずに没入型の全画面で表示（画面タップまたは戻る操作で終了）
- 外部送信なし（インターネット権限も未使用）

## 動作条件

- Android 16（API 36）以降
- 個人所有端末での利用を前提
- カメラを搭載した実機
- Android Studio Meerkat 2024.3.1以降を推奨
- JDK 17
- Android SDK 36

## ビルドとインストール

1. Android Studioでこのリポジトリを開きます。
2. Android SDK 36が未導入なら、SDK Managerから追加します。
3. USBデバッグを有効にしたAndroid実機を接続します。
4. `app` 構成を選び、Runを押します。

コマンドラインの場合:

```bash
./gradlew testDebugUnitTest assembleDebug
adb install -r app/build/outputs/apk/debug/app-debug.apk
```

## 使い方

1. 撮影間隔、動体検知の閾値、アイコン色を選びます。
2. 「開始してバブル化」を押します。
3. 初回だけ、カメラ・通知・他のアプリ上への表示を許可します。
4. カメラ準備後にアプリが背面へ移動し、バブルが表示されます。
5. 必要なら、撮影中であることを確認してから画面をロックします。
6. バブルをドラッグして移動、タップしてアプリへ戻れます。
7. 停止はアプリ画面または常駐通知の「停止」から行います。
8. 動体検知は常に有効です。最初の1回は比較用で保存されず、以降はカメラごとに前回の画像と比べ、どれかで動体があったときだけ全カメラの画像を `IBC_MOTION_<日時>_<カメラ>.jpg`（例: `_back0`・`_back2`・`_front1`。数字は端末のカメラ番号）として保存します。
9. 「画像を全画面表示」を押すと同梱画像が開きます。画像をタップするか戻る操作で閉じます。

## Androidの制約と注意点

- Androidのプライバシー仕様により、撮影中はカメラ使用インジケーターと常駐通知が表示されます。非表示にはできません。
- 7色設定で変わるのはアプリのランチャーアイコンとバブルだけです。ブラックを選んでも、Android右上の緑色カメラ使用表示の色は変更されません。
- Android 16以降のバックグラウンドカメラ制約に対応するため、撮影サービスは必ず画面ロック前かつアプリ画面が前面にある状態で開始します。その後はカメラ用フォアグラウンドサービスとして継続します。
- 画面ロック中は部分Wake Lockを撮影ごとに更新します。停止時や異常終了時には必ず解放します。
- Androidで同時に開けるカメラは最大2台です。前後の同時撮影には端末の対応（`FEATURE_CAMERA_CONCURRENT`）が必要で、非対応の端末や3台目以降は毎回カメラを切り替えて撮ります。切り替え1回に約1秒かかるため、カメラが多いと短い間隔では設定より間隔が延びます。
- ピントは動いた画素の重心に合わせ、以降の撮影もその位置に合わせます。ピント合わせは1台あたり最大2秒、動体を検知したカメラは撮り直しの分さらに長くかかるため、短い間隔では設定より間隔が延びます。
- 超広角や望遠をアプリに公開していない機種では、それらのカメラは使えません。背面のメインカメラと、その中の物理カメラ（広角など）が両方撮影されるため、似た画像が2枚保存されることがあります。
- 動体検知は撮影画像を80×60画素の輝度画像に縮小し、明るさ全体の変化（自動露出）を差し引いてから、変化した画素の割合で判定します。カメラ自体が動くと動体として扱われるため、端末は固定して使ってください。
- 検出は、閾値を超える変化があったときと、追跡中の対象がいるあいだだけ動かします（電池と発熱を抑えるため）。追跡中は変化が閾値未満でも位置の移動で動きを拾うので、ゆっくり歩く人も追えます。風で揺れる木や光の変化だけでは保存しません。
- 足だけが写っている場合は、脚の一部も写っていないと検出できないことがあります（足先だけを検出できる端末内モデルが無いため）。
- 検出モデル3つ（合計約18MB）と実行部品の分、アプリが大きくなっています。
- APKには64ビットARM（`arm64-v8a`）向けの実行部品だけを入れています。Android 16の実機（OPPO A5 5Gなど）はこれで動きますが、x86のエミュレーターでは動きません。
- 1秒間隔は端末の発熱、電池消費、保存容量への負荷が大きくなります。
- 指定値は撮影開始時刻の目標間隔です。カメラの処理が指定間隔より長い場合は、写真を重複して処理せず、前の保存完了後すぐ次を撮影します。
- 極端な省電力モードやメーカー独自のバックグラウンド制限により、ロック中の間隔が遅れたりサービスが停止したりすることがあります。
- カメラを利用する別アプリとは同時に撮影できません。

## 実装概要

- Kotlin / Android Views
- CameraX `ImageCapture`
- `LifecycleService` + `foregroundServiceType="camera"`
- `PARTIAL_WAKE_LOCK`（10分の安全タイムアウトを各撮影前に更新）
- `TYPE_APPLICATION_OVERLAY` のフローティングバブル
- MediaStore / scoped storage
- Min/Target SDK 36（対応OSの上限なし）、CameraX 1.6.1

## プライバシー

写真は端末の共有Pictures領域だけに保存します。アプリはインターネット権限を宣言せず、写真・利用情報を外部へ送信しません。撮影は端末所有者がアプリ画面から明示的に開始した場合に限られ、常駐通知とバブルから状態を確認・停止できます。
